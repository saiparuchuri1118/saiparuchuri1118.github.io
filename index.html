Case study · Amazon · Amazon Bedrock

A support bot that checks its own answers

Problem

A security team's Slack channel receives ~90 customer questions a day. Engineers answered them in the order they arrived, so a question waited 24 hours or more for its first reply.

Approach

A three-agent system on Amazon Bedrock using Claude Opus 4.6. A retrieval agent finds the right knowledge, a critic agent validates each draft against several criteria before it posts, and a self-learning agent reviews the day's channel activity and corrects answers from user feedback.

Result

First replies now arrive in under 60 seconds, a 99% reduction in response time. Every answer carries thumbs-up and thumbs-down feedback, and the bot holds a 78% CSAT.

Design decisions

Hybrid retrieval
Keyword search (BM25) catches exact terms like tool names and error codes that embeddings blur. Dense vectors catch questions phrased differently from the docs. A reranker orders the merged results so the model sees the best passages first.
A critic before every reply
A second agent reviews each draft before anyone sees it. Answers that are unsupported or incomplete never reach the channel.
Learning from the channel
The self-learning agent reads a day of feedback at a time, so the bot gets better without a retraining cycle.

Open source

Python · MIT license · github.com/saiparuchuri1118/ragscope

ragscope: a CI gate for RAG retrieval quality

Most RAG projects ship a chatbot and check a few answers by eye. ragscope measures retrieval against a golden dataset, compares every run with a committed baseline, and fails the build when quality drops. A chunking change that quietly costs recall never reaches production.

Rank-aware metrics
Hit rate, precision, recall, MRR and nDCG at any cutoff, with graded relevance judgments.
Thresholds and baselines
Thresholds catch a pipeline that was never good enough. Baselines catch a slow slide. Tolerance is absolute, so it doesn't loosen as scores fall.
Tested like infrastructure
184 tests at 100% line and branch coverage on Python 3.9 to 3.13. A CI canary plants an off-by-one bug and requires the gate to reject it.
Drops into any stack
Zero runtime dependencies. Anything with a retrieve(query, k) method can be evaluated.
